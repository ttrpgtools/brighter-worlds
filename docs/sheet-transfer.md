# Account-free old-site sheet transfer

The root character library now offers **Find sheets from the old site** in a prominent callout, including when local or account characters already exist. The home page links to the `/migrate` guide, which also offers the popup action at root. A click opens the fixed `https://dev.brighterworlds.app/migrate` route. Both origins must serve this compatible application before the direct flow is available. This implementation does not change hosting or redirect any dev route. See [migration-guidance.md](migration-guidance.md) for account/file routes and recovery scope.

The old-site page reads local sheets from that browser/profile and selects all readable sheets by default. **Select all** and **Deselect all** accompany the checkboxes and selection count. **Copy selected sheets to brighterworlds.app** builds and validates the selected sheets and their companions, then explicitly authorizes sending that snapshot. There is no intermediate source review screen. No inventory or character content is sent before that action. The destination validates the complete backup, shows which sheets will be added or are already present, and requires **Copy these sheets** before importing. An account, a cloud save and cloud availability are not prerequisites. Account characters remain in the separate account library.

The destination reuses the [portable backup importer](backups.md). Conflicts are based on the saved sheet ID and content, not on names. The conflict selector appears only when a different version exists. **Keep both: copy with new IDs** preserves the incoming sheets and their companion relationships with fresh IDs, adding **(copy)** to the new names (**copy 2**, etc. when needed). **Keep existing sheets and skip conflicts** preserves current records. Names alone never cause a conflict. Originals are never deleted. Companion and image validation, HTML sanitization, transaction rollback and stale-preview checks follow the file importer.

After copying, per-sheet results and **View characters** are the primary actions. A connection retry stays with the copy workflow and is absent after success. Optional **Save a backup file** explains that it downloads the selected old-site sheets. File-based recovery instructions and **Open backup tools** are shown when needed, rather than being mixed with successful copy results.

## Protocol and limits

Implementation: `src/lib/data/sheet-transfer/{protocol,source,destination}.ts`.

- Fixed peer origins are `https://brighterworlds.app` and `https://dev.brighterworlds.app`. The receiver also checks the exact returned pop-up or captured opener window. Neither endpoint accepts a return origin from a URL or message.
- A fresh UUID session appears only in the fragment of the fixed pop-up URL. Character data, account credentials and Discord webhooks are never put in URLs. Portable field allowlists exclude private settings and account metadata from payloads.
- The `brighter-worlds.sheet-transfer` envelope has protocol version 1, a session and an operation. Strict operation validators reject unexpected fields, versions, origins, windows, sessions, malformed IDs, invalid indices and over-limit data. Operations are `hello`, `ready`, `inventory`, `request`, `chunk`, `review`, `result`, `error` and `cancel`. All sends use an exact target origin; none use `*`.
- `hello`/`ready` establish the handshake and provide one-second heartbeats. Only explicit source confirmation sends `inventory`: a SHA-256 digest, UTF-8 byte size, chunk count, record count and selected root IDs. It contains no names or descriptions. The destination pulls sequential chunks, verifies the complete text's digest/length, and validates the v1 bundle and confirmed manifest before presenting a preview. No sheet is imported from a partial payload.
- A bundle is limited to 16 MiB and 1,000 sheets, including companion closure. Text is sent in at most 32 Ki UTF-16 code units per chunk, pulled one part at a time with destination progress. Unicode text is reassembled before UTF-8/digest checks. Results are limited to 100 records per message; the source only reports completion after all distinct selected records have corresponding outcomes.
- Every received operation is gated by the current phase. Heartbeat loss times out after 20 seconds; stalled payload/validation progress times out after 60 seconds even if heartbeats continue. A session expires absolutely after 30 minutes. Closing, page navigation, component teardown and cancellation end the session; ended sessions ignore later messages. Cross-origin navigation cannot be inspected directly, so loss of that document's heartbeat also closes the connection.

This follows the browser's [postMessage origin/window checks](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage) and [user-initiated pop-up constraints](https://developer.mozilla.org/en-US/docs/Web/API/Window/open). COOP, privacy settings and pop-up blockers may sever or prevent an opener relationship; the file path below remains available.

## Durability and retries

The importer commits each selected graph atomically with its original-byte recovery archive and content-bound receipt. Only verified durable results are acknowledged. Skipped conflicts are reported as skipped, not as copied. A quota or write failure rolls back all writes in that transaction; the destination retains and refreshes the preview for retry. No partial successful acknowledgment is sent.

The import receipt identifies source provenance, selected roots, validated content, policy and actual destination IDs; it intentionally excludes session IDs and volatile export metadata so a new pop-up session can safely retry the same selection. Source root IDs are sorted before export, so changing checkbox click order also retains this identity. Retrying after a lost acknowledgment returns **already applied** and does not duplicate a graph, overwrite later destination edits or resurrect deleted copies.

A second durable `bw-popup-transfer:v1:{session}:{content-digest}:{policy}` receipt records the pop-up session, fixed source origin, content digest, chosen policy and per-record destination outcomes. It is written and read back before transmitting results. If that receipt fails after the sheet transaction has committed, no success is sent; the existing importer receipt makes a retry safe. This metadata lives outside the sheet scan namespace and is excluded from portable exports.

## Recovery and verification

If a pop-up is blocked, closed, loses its opener, expires or cannot read storage, the destination offers the fixed old-site export link and **Backups and restore**. The source `/migrate` route also works as a standalone file-export page without an opener/session. Selecting sheets and downloading a portable backup remain possible after a failed connection. The destination can download a fully validated received backup even after disconnection. Damaged records are reported with a link to the local library's private recovery archive; they are not silently presented as copied. Missing companions are explicitly warned about in both previews.

Both `/migrate` and existing character deep links remain accessible without configured auth services or during an auth outage. The dedicated `/migrate` route skips ordinary account verification even when a sign-in cookie exists, so a stalled verifier cannot hold up local recovery. Explicit auth completion URLs retain the existing auth flow. No dev redirect is implemented; a future landing-page-only redirect requires separate preparation and validation.

Automated tests cover exact-origin/window/session/schema rejection; source consent; chunk ordering and Unicode; corrupt/transit-modified content; companion closure and graph remapping; batched results; conflicts; rollback; interrupted/lost acknowledgments; receipt failure after sheet commit; unchanged source storage; private-field exclusion; selection order; timeouts; and anonymous/auth-outage route access. Run `pnpm test:unit --run` and `pnpm check`. Fake peer windows and IndexedDB tests do not establish cross-origin compatibility in real browsers.
